# NuviraHub — Installation on Windows

[← Index](README.md)

Choices made with the user (2026-10-27): one program that runs without installing and can install itself (like Supremo and AnyDesk), the server in the file name (like RustDesk), a classic NSIS setup for scripted installations.

## One program

`nuvira.exe` is the app and also contains the other programs, started on itself:

| Command | What it is |
|---|---|
| `nuvira.exe` | the app (Tauri) |
| `nuvira.exe viewer ...` | session window, started by the app for each connection |
| `nuvira.exe agent ...` | controlled device from the command line; started this way by the service |
| `nuvira.exe service install / status / uninstall / run` | unattended access (see [14-phase3-service.md](14-phase3-service.md)) |

One file to download, copy and sign: 28 MB instead of four programs totalling 41 MB, with the C runtime linked in (no DLLs next to it). The viewer, the agent's command line and the service are libraries with a `run(args)` function; `nuvira-viewer.exe`, `nuvira-agent.exe` and `nuvira-service.exe` are still built for development and tests.

The app is a windowed program: from a command prompt the subcommands attach to the prompt's console and open its handles (Windows does not give them to a windowed program).

## Server in the file name

```
nuvira-host=nuvira.example.com.exe
nuvira-host=10.0.0.5,port=21117,key=<64-hex fingerprint>.exe
```

Whoever hosts a server hands out the same program, renamed: at start-up it saves that server (and the fingerprint, pinned for agent and viewer) in its settings and connects with no setup. `:` is not allowed in Windows file names, hence `port=`. A browser's ` (1)` suffix is ignored; a bad port or key is dropped. Changing the server by hand forgets the fingerprint. The setup reads the same options from its own name (`nuvira-setup-host=....exe`).

## Install from the app

Settings → Unattended access → "Install on this computer": permanent password (empty: generated and shown once), then the administrator prompt (UAC). The app runs `nuvira.exe service install` as administrator:

- the password goes in a temporary file deleted at once (`--password-file`), not on the command line, which other programs can read;
- the outcome comes back as JSON in another file (`--report`): the app cannot see the output of a process started as administrator;
- once installed the app switches to the service's agent (same ID and passwords as the service).

The installation copies the program to `%ProgramFiles%\nuvira\nuvira.exe`, installs the service, opens the firewall for the direct path, enables Ctrl+Alt+Del for services and adds:

- a Start menu shortcut (all users);
- an entry in the installed apps, whose uninstall command is `nuvira.exe service uninstall --remove-program`: it asks for administrator rights by itself and removes service, firewall rule, entry, shortcut and the program folder. The data in `%ProgramData%\nuvira` stays, so reinstalling keeps the device ID.

Updating over a running installation: a running program cannot be overwritten but can be renamed, so the installed one is moved aside (`nuvira.old.exe`, deleted at the next update) when the copy fails.

## Setup (NSIS)

`tools/build-setup.sh` builds `dist/nuvira-setup.exe` (6.6 MB) from `deploy/windows/nuvira-setup.nsi`, downloading NSIS 3.08 once into `target/tools` (the archive Tauri uses, checked against its SHA-256).

The setup is a wrapper around the same installation: it unpacks `nuvira.exe` into a temporary folder and runs `service install`, so there is one installation logic. Pages: welcome, licence (AGPL-3.0), server and permanent password, progress, finish with "Run NuviraHub" (started through Explorer, so not as administrator). Languages: English, Italian, French, German, Spanish, chosen from Windows.

```
nuvira-setup.exe                                    wizard
nuvira-setup.exe /S [/SERVER=host[:port]] [/PASSWORD=...] [/KEY=fingerprint]
```

Without a server (neither `/SERVER=` nor in the file name, field left empty) the NuviraHub public server is used, also in a silent installation.

## Customised programs (NuviraHub Pro)

A program generated by the web console of a Pro server (entitlement `CUSTOM_INSTALLER`) carries a JSON document appended after the executable image, followed by its length (u32, little endian) and `NUVIRA-BRAND1` (`client/service/src/branding.rs`): kind (`quick` for quick support, `full`), name shown, PNG logo, colour, support message and contacts, server and its fingerprint, language, locks for server and language. Windows ignores those bytes.

- The app reads it at start-up (`client/app/src/branding.rs`), drops what is not valid and keeps a copy in its data folder: an automatic update brings the standard program, the customisation stays. An installation keeps a copy next to the program (`Program Files
uviraranding.json`), readable by every user.
- Server and language of the document win over the file name; locked ones cannot be changed from the app (the commands refuse them too).
- Quick support shows only this computer's ID, password and chat: no address book, settings or installation.
- The NuviraHub credits stay visible (additional term 7(b)).
- The format is open, like the client: the value of Pro is the generator and the profiles. A future version may sign the document with the server's key.
- Code signing (to do) will need the document elsewhere: bytes after an Authenticode signature invalidate it.
